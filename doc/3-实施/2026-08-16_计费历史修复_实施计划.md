# 计费历史弹窗修复 — 实施计划

结论：钱包页"计费历史"弹窗存在三个前端问题——(1) 弹窗打开时不重新拉数据，兑换成功后仍显示旧(空)缓存；(2) 金额单位错位，把令牌数当 USD 显示（兑换 $1 的码显示 $500,000）；(3) 兑换码记录的支付方式列显示原始字符串 `redemption`。本计划为纯前端最小改动修复，不触碰后端写入逻辑与查询过滤；影响：钱包页"计费历史"弹窗的展示与刷新行为；范围：`web/src/features/wallet/components/dialogs/billing-history-dialog.tsx`、`web/src/features/wallet/hooks/use-billing-history.ts`、`web/src/features/wallet/lib/billing.ts`、i18n 7 语种 locale；非范围：后端 `model/redemption.go`/`model/topup.go`/`topup/self` 查询、react-query 重构。

## 1. 背景与根因

### 1.1 弹窗打开不刷新
`BillingHistoryDialog`(`web/src/features/wallet/components/dialogs/billing-history-dialog.tsx`)在 `web/src/features/wallet/index.tsx:341-344` 常驻挂载，`open` 仅控制显隐。数据 hook `web/src/features/wallet/hooks/use-billing-history.ts:156-160` 的 `useEffect` 只在 `debouncedKeyword`/`page`/`pageSize` 变化时调用 `fetchBillingHistory()`，**打开弹窗不触发刷新**。因此兑换成功后再次打开弹窗，看到的是上一次(空)的缓存数据。

### 1.2 金额单位错位
后端 `TopUp.Amount`(int64, `model/topup.go:17`)的语义**因支付方式而异**（已核实）：
- 兑换码(`model/redemption.go:188`)与 creem(`controller/topup_creem.go:119`)：存**令牌数**(quota)。兑换 $1 码时 `redemptions.quota = 1 × QuotaPerUnit = 500,000`，`Amount=500000`。
- epay/stripe/waffo/waffo_pancake：`Amount` 存 **USD 数额**；`Money` 存 USD 实付。
- 订阅相关：`Amount` 恒 0，仅 `Money` 有效。

前端弹窗 `billing-history-dialog.tsx:244` 用 `formatCurrencyFromUSD(record.amount)` 对所有记录一律当 USD 显示——兑换码记录 500,000 被显示为 `$500,000`(正确应 `$1`)；creem 记录同样错 50 万倍。`record.money`(支付列)对兑换码为 0 属正常语义（无实付）。

**正确显示规则**：`money` 非 0（在线支付）→ `formatCurrencyFromUSD(money)`；`money` 为 0 且为兑换码(`payment_method=redemption`)→ `formatQuotaWithCurrency(amount)`（令牌数÷quotaPerUnit→USD）。

### 1.3 支付方式名缺失
`web/src/features/wallet/lib/billing.ts:61-66` 的 `PAYMENT_METHOD_NAMES` 无 `redemption` 条目，导致支付方式列显示原始字符串 `redemption`。

## 2. 修复方案（纯前端，3 处小改 + i18n）

1. **金额显示修正**(`billing-history-dialog.tsx:243-249`)：按 `record.money` 是否非零分支——
   - `money > 0`：`formatCurrencyFromUSD(record.money, …)`（在线支付 USD 实付）
   - 否则（兑换码等 `Amount` 为令牌数且 `money=0`）：`formatQuotaWithCurrency(record.amount, …)`
   移除 `formatNumber(record.money)` 的"支付"列对兑换码的误导？——保留支付列，但仅对在线支付显示 `money`（`formatCurrencyFromUSD` 化）；兑换码记录该列显示 `-` 或按 `formatQuotaWithCurrency` 显示等价金额。**以最终实现为准，目标是三种模式(USD/CNY/TOKENS)下金额正确、无"未支付"误导。**
2. **弹窗打开时刷新**(`use-billing-history.ts` + `billing-history-dialog.tsx`)：hook 增加 `open` 参数，新增 `useEffect([open])`，`open` 变 true 时 `setPage(1)` 并 `fetchBillingHistory()`；弹窗把 `open` 传给 hook。翻页/搜索/并发保护(`requestIdRef`)逻辑不变。
3. **支付方式名**(`lib/billing.ts` + i18n)：`PAYMENT_METHOD_NAMES` 增加 `redemption: 'Redemption Code'`；按项目 i18n 流程(`web/scripts/add-missing-keys.mjs` + `node scripts/sync-i18n.mjs`)写入 7 语种(zh 译"兑换码")。

## 3. 验证

- `cd web && bun run build`(含 tsc)通过，无 `noUnusedLocals`/类型错误。
- i18n：add-missing-keys + sync-i18n 后 7 locale `Redemption Code` missing=0、untranslated=0。
- 手动：兑换 $1 码 → 打开"订单历史"→ 立即显示记录，金额 `$1`、支付方式"兑换码"、状态 Success。

## 4. 不改动

- 后端 `model/redemption.go`(已正确写 `Amount=quota`)、`model/topup.go`、`topup/self` 查询(已覆盖 redemption)。
- `formatNumber(record.money)` 语义本身；不引入 react-query。
